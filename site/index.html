Search NRC ADAMS
without the filter gymnastics.

A small Bun + Elysia API in front of the ADAMS Public Search API. Plain query parameters in, clean JSON out.

View on GitHub Get an ADAMS API key

Why

The upstream search endpoint takes a JSON body whose filters are objects like {"field","value","operator"}, even though the published spec says strings. This wrapper hides that behind a GET /search you can call from a browser or curl, and keeps your subscription key on the server.

Quick start

git clone https://github.com/maxoliverbr/adams-public-search
cd adams-public-search
bun install
echo "ADAMS_API_KEY=your-key" > .env
bun run dev          # http://localhost:3000

Examples

# one document by accession number
curl localhost:3000/documents/ML20055E745

# search: docket + date range, newest first
curl 'localhost:3000/search?q=reactor&docket=05000390&from=2020-01-01&to=2020-12-31&sort=DocumentDate&order=desc'

# two dockets (OR), main library only
curl 'localhost:3000/search?q=steam+generator&docket=05000390&docket=05000391&library=main'

Endpoints

RouteWhat it does
GET /documents/:accessionOne document by ML number.
GET /searchSimplified search. Results omit the large content field unless content=true.
POST /searchRaw passthrough of the upstream request body.
GET /openapiInteractive API docs. Spec at /openapi/json.

Search parameters

ParamMeaning
qSearch text (default *).
docket, typeExact match. Repeat the param for any-of.
author, addressee, keywordContains match. Repeat for any-of.
from, toDocument date range, YYYY-MM-DD.
librarymain, legacy or all (default).
sort, orderField name and asc / desc.

This site is static documentation. The API itself is self-hosted: it needs your own ADAMS subscription key, which must never be published in a browser.
