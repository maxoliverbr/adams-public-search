NRC ADAMS search, one GET request away.

A small API in front of the ADAMS Public Search service. Plain query parameters in, clean JSON out. NUREGs, letters, inspection reports and more, without hand-building filters. Typed end to end, with a generated OpenAPI spec and an Eden client.

Get startedView on GitHubDocumentation

# reactor documents on one docket in 2020, newest first
curl -G localhost:3000/search \
  -d q=reactor -d docket=05000390 \
  -d from=2020-01-01 -d to=2020-12-31 \
  -d sort=DocumentDate -d order=desc

Built to be dependable

Everything you need to query ADAMS without wrestling its request format.

🔎

Simple search

GET /search with q, docket, type, author, keyword, date range, library and sorting.

📄

Document lookup

GET /documents/:accession returns one document by ML number, unwrapped.

🛡️

Typed end to end

Requests and responses share one schema for runtime validation and static types. Bad dates and enums get a 422.

🔗

Eden client

Export type App and get an autocompleting, compile-checked client with treaty<App>.

✅

Validated upstream

Every ADAMS response is checked before it is returned. A changed shape becomes a clear 502, not wrong data.

📘

OpenAPI docs

Interactive docs at /openapi and a JSON spec at /openapi/json, with response shapes.

🔑

Key stays server-side

Your ADAMS subscription key is added upstream and never exposed to callers.

🔁

Raw passthrough

POST /search forwards a typed upstream body for anything the simple params can't express.

Type-safe, from query to response

The server's types flow straight into your client. No codegen, no hand-written interfaces.

import { treaty } from "@elysiajs/eden";
import type { App } from "../src/index";

const api = treaty<App>("localhost:3000", {
  parseDate: false,
});

const { data, error } = await api.search.get({
  query: { q: "reactor", docket: "05000390" },
});
if (error) throw new Error(`ADAMS ${error.status}`);

// typed: string | null | undefined
data.results[0]?.DocumentTitle;

// library: "nope" is a compile error
// and a 422 at runtime
RequestsQuery params are validated at runtime and typed from the same schema.
ResponsesEvery ADAMS response is validated before it is returned. If ADAMS changes shape you get a 502 naming the field.
Schemas that match realityThe published spec corrected against a live survey of 500 documents: nullable fields, string-valued codes, extra fields.
ErrorsUpstream statuses (400, 401, 403, 404, 429, 500, 502) are typed on error.status.

Quick start

Install, configure, search.

# run it
bun install
echo "ADAMS_API_KEY=your-key" > .env
bun run dev   # http://localhost:3000
# one document by accession number
curl localhost:3000/documents/ML20055E745

# two dockets (OR), main library only
curl -G localhost:3000/search \
  -d docket=05000390 -d docket=05000391 \
  -d library=main

This site is static documentation. The API is self-hosted and needs your own ADAMS subscription key (get one here), which must never be published in a browser.
